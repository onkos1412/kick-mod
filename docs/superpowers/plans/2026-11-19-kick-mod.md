# Kick Mod Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Minecraft Java mod that lets a player kick a mob or player (1 heart, armor applies, big knockback, visible leg animation), built from one codebase for Fabric/NeoForge/Forge across 1.20.1–26.3.

**Architecture:** One Java source tree; Stonecutter generates one Gradle node per `<mcVersion>-<loader>` and switches version/loader differences via `//? if` comments. All rules (validation, cooldown, knockback math, config parsing) live in pure Java classes with no Minecraft imports and are unit-tested with JUnit; Minecraft-facing code is thin and verified in-game. Loader differences go through a small `Platform` interface implemented once per loader.

**Tech Stack:** Gradle (wrapper) + Stonecutter; Fabric Loom (Fabric), ModDevGradle (NeoForge), ModDevGradle Legacy (Forge); Mojang official mappings; Mixin; JUnit 5; Gson (bundled with Minecraft) for config. JDK 21 and 25 are installed; Gradle toolchains provision JDK 17 for 1.20.1.

**Spec:** `docs/superpowers/specs/2026-11-19-kick-mod-design.md`

## Global Constraints

- Mod id `kick`; display name `Kick!`; Java package `com.kickmod.kick`.
- Version matrix (Stonecutter nodes): `1.20.1-fabric`, `1.20.1-forge`, `1.21.1-{fabric,neoforge,forge}`, `1.21.4-{fabric,neoforge,forge}`, `1.21.11-{fabric,neoforge,forge}`, `26.1.2-{fabric,neoforge,forge*}`, `26.3-{fabric,neoforge,forge*}`. `*` = only if a Forge build for that MC version exists at build time; otherwise drop the node and note it in README. Add a `26.2` node only if the 26.3 jar does not load on 26.2.
- Each jar declares the patch range it supports (e.g. 1.21.1 node: `>=1.21 <=1.21.1`).
- No runtime dependency other than the loader itself and Fabric API (Fabric only). No Architectury API, no config library.
- Server is authoritative: client sends only "I kicked entity N"; the server decides everything.
- Defaults: `damage=2.0`, `knockbackMultiplier=1.5`, `knockbackUp=0.4`, `cooldownTicks=20`, `reach=3.0`, `allowKickPlayers=true`. Key `V`, category "Kick!".
- Damage type `kick:kick` must NOT be in `minecraft:bypasses_armor` (armor, Protection and Resistance reduce it); `scaling: "never"`.
- Death messages: en_us `"%1$s was kicked to death by %2$s"` / ru_ru `"%1$s был запинан %2$s"`; no-attacker variants `"%1$s was kicked to death"` / `"%1$s был запинан"`.
- Translations shipped: `en_us`, `ru_ru`.
- A client with the mod must be able to join a server without it, and vice versa, without crash or disconnect.

## Review Focus

1. Hacked client sends a far/behind-a-wall/invalid entity id → server rejects silently (no damage). Tests: `KickRulesTest.rejectsTooFar`, `rejectsNoLineOfSight`, `rejectsMissingTarget` (Task 2).
2. Packet spam faster than cooldown → only one kick per `cooldownTicks`, server-side. Test: `KickCooldownsTest.blocksUntilCooldownElapses` (Task 2).
3. Kicking players when PvP is off / `allowKickPlayers=false` / kicking self / spectator kicker / dead target → rejected. Tests: `KickRulesTest.rejectsPlayerWhenPvpOff`, `rejectsPlayerWhenDisabledInConfig`, `rejectsSelf`, `rejectsSpectatorKicker`, `rejectsDeadTarget` (Task 2).
4. Config file missing, malformed JSON, or negative/huge values → defaults or clamped values, never a crash. Tests: `KickConfigTest.*` (Task 2).
5. Client with mod on server without mod presses `V` → nothing happens, no exception, no log spam. Check: Task 6 Step 4 (in-game, needs a vanilla server).

### Task 2: Pure rules, cooldowns and config (no Minecraft imports)

**Files:**
- Create: `src/main/java/com/kickmod/kick/logic/KickConfig.java`
- Create: `src/main/java/com/kickmod/kick/logic/KickRules.java`
- Create: `src/main/java/com/kickmod/kick/logic/KickCooldowns.java`
- Test: `src/test/java/com/kickmod/kick/logic/KickConfigTest.java`, `KickRulesTest.java`, `KickCooldownsTest.java`

**Interfaces:**
- Produces: `record KickConfig(double damage, double knockbackMultiplier, double knockbackUp, int cooldownTicks, double reach, boolean allowKickPlayers)` with `static KickConfig defaults()`, `static KickConfig parse(String json)` (never throws; bad/missing fields → default; clamps: damage 0–100, knockbackMultiplier 0–10, knockbackUp 0–2, cooldownTicks 0–1200, reach 1–6), `String toJson()`.
- Produces: `record KickAttempt(boolean kickerAlive, boolean kickerSpectator, boolean targetExists, boolean targetIsSelf, boolean targetAlive, boolean targetIsLiving, boolean targetIsPlayer, boolean pvpAllowed, double distance, boolean lineOfSight)`.
- Produces: `enum KickDenial { NONE, KICKER_INVALID, NO_TARGET, SELF, TARGET_DEAD, NOT_LIVING, TOO_FAR, NO_LINE_OF_SIGHT, PVP_DISABLED }`; `static KickDenial KickRules.check(KickAttempt a, KickConfig c)`. Reach tolerance: `distance <= c.reach() + 1.0` (ping slack).
- Produces: `static double[] KickRules.knockback(float yawDegrees, KickConfig c)` → `{x, y, z}`: horizontal unit vector of the yaw (MC convention: `x = -sin(yaw)`, `z = cos(yaw)`) times `0.4 * c.knockbackMultiplier()` (0.4 = vanilla base knockback), `y = c.knockbackUp()`.
- Produces: `final class KickCooldowns` — `boolean tryUse(UUID player, long gameTick, int cooldownTicks)` (true and records if elapsed), `void forget(UUID player)`.

### Task 5: Server kick handler

**Files:**
- Create: `src/main/java/com/kickmod/kick/KickHandler.java`

**Interfaces:**
- Consumes: `KickRules.check`, `KickRules.knockback`, `KickCooldowns`, `KickConfigFile.get()`, `KickRegistry.source`, `KickRegistry.KICK_SOUND`, `Platform.broadcastKickAnim`.
- Produces: `static void KickHandler.onRequest(ServerPlayer kicker, int targetId)`; `KickHandler.onPlayerLeave(UUID)` → `cooldowns.forget`.

- [ ] **Step 1:** Implement: cooldown via `tryUse(uuid, level.getGameTime(), cfg.cooldownTicks())` first — if false, return silently. Always `broadcastKickAnim(kicker)` after cooldown passes (even on denial / air kick). Build `KickAttempt` from the world (distance = eye of kicker to target bounding box nearest point; LoS = `kicker.hasLineOfSight(target)`; pvp = `server.isPvpAllowed()` and `kicker.canHarmPlayer(target)` for player targets). On `NONE`: `target.hurt(source, cfg.damage())`; if it returned true, apply knockback vector from `KickRules.knockback(kicker.getYRot(), cfg)` scaled by `(1 - target knockback resistance attribute)`, set `hurtMarked = true`; play `KICK_SOUND` at target; spawn ~8 `POOF` particles at target's mid-height. On an air kick (`targetId == -1`) or any denial, play vanilla `ENTITY_PLAYER_ATTACK_NODAMAGE` (whoosh) at the kicker instead. Denials are not logged above debug.
- [ ] **Step 2:** Hook player-disconnect → `onPlayerLeave` in each loader entrypoint.
- [ ] **Step 3: Verify in-game** with the Task 4 debug sender (`1.21.1-fabric`, `26.3-neoforge`): zombie loses 2 HP and flies ~3–4 blocks with a hop; zombie in iron armor loses less; second request within 1 s does nothing; request for an entity 10 blocks away does nothing.
- [ ] **Step 4: Commit** `feat: server-side kick handling`.

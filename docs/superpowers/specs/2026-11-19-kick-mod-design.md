# Мод «Пинок» — дизайн

Дата: 2026-11-19
Статус: одобрено (версии 1.20.1–26.3; Forge на 26.x — только если загрузчик доступен)

## Зачем

Весёлый мод-шутка для Minecraft Java: игрок может пнуть ногой моба или другого игрока. Пинок должен быть смешным (заметный отлёт, звук, видимая нога), но не ломать игру: он отнимает одно сердце, а броня работает как обычно.

Мод должен работать на всех актуальных версиях и основных загрузчиках модов, при этом поддерживаться из одной кодовой базы.

## Цели

- Пинок по клавише, по сущности, на которую смотрит игрок.
- Урон 1 сердце (2.0 HP), броня и зачарования защиты уменьшают его как обычный урон.
- Сильный, смешной отлёт с подбросом вверх.
- Видимая анимация ноги: от первого лица (у себя) и от третьего (у других игроков).
- Звук и частицы при попадании.
- Работает на Fabric, Quilt (через Fabric-сборку), NeoForge, Forge.
- Версии от 1.20.1 до последней стабильной (сейчас 26.3).

## Не цели

- Серверный плагин (Paper/Spigot/Purpur) — отдельный продукт, не делаем.
- Новые предметы, блоки, зачарования, достижения.
- Пинок блоков (дверей, предметов на земле и т.п.).
- Публикация на Modrinth/CurseForge и автопубликация — не в этой работе (сборка должна давать готовые jar, которые можно опубликовать вручную).
- Версии старше 1.20.1.

## Анти-цели (провал, даже если «работает»)

- Пинок как читерское оружие: спам без кулдауна, урон сквозь броню, пинок через стены или с большого расстояния.
- Пинок игроков на сервере с выключенным PvP.
- Решения о попадании принимает клиент (можно взломать). Сервер — единственный источник правды.
- 15 копий почти одинакового кода, которые расходятся между собой.

## Механика (поведение)

**Нажатие.** Клавиша по умолчанию `V`, переназначается в «Управление», категория «Пинок». На клиенте при нажатии: если кулдаун не истёк — ничего; иначе проигрывается анимация ноги у себя и на сервер уходит пакет «пинок» с id сущности под прицелом (или без цели — тогда пинок «в воздух», только анимация и звук взмаха).

**Проверки на сервере** (при провале цель не получает урон, но анимация у других всё равно проигрывается):
- кулдаун игрока истёк (сервер ведёт свой таймер, клиентский — только для отзывчивости);
- игрок жив, не в режиме наблюдателя;
- цель существует, жива, это `LivingEntity`, не сам игрок;
- расстояние до цели ≤ дальности (по умолчанию 3.0 блока, считать как ванильная проверка дальности атаки с небольшим запасом на пинг);
- есть прямая видимость (как у ванильной атаки);
- если цель — игрок: на сервере включён PvP и обе стороны могут атаковать друг друга (уважать команды/scoreboard так же, как ванильная атака).

**Эффект при попадании:**
- урон 2.0 через собственный тип урона `kick:kick` (data-driven damage type), источник — пинающий игрок. Тип урона НЕ в теге обхода брони, поэтому броня, «Защита» и сопротивление уменьшают урон;
- отлёт: горизонтальный импульс в направлении взгляда пинающего ×1.5 к силе (настраивается), плюс вертикальный подброс ~0.4. Сопротивление отбрасыванию (например, у незеритовой брони) уменьшает отлёт как обычно;
- сообщение о смерти: «%1$s был запинан %2$s» / «%1$s was kicked to death by %2$s» (en_us + ru_ru);
- звук: смешной «бум/шлепок» (свой звук `kick:entity.kick`, файл .ogg в ресурсах) и несколько частиц на месте удара;
- мобы реагируют как на обычную атаку (агрятся, убегают и т.п.) — это даёт ванильный механизм урона.

**Кулдаун:** 20 тиков (1 с) по умолчанию. Обычная атака рукой и пинок не делят кулдаун.

**Анимация:**
- У себя (первое лицо): нога снизу экрана делает быстрый выпад вперёд и возвращается (~6 тиков).
- У других (третье лицо): правая нога модели игрока делает махом вперёд. Сервер рассылает игрокам поблизости пакет «X пнул», клиент проигрывает анимацию.

**Если мод есть только у клиента** (сервер без мода): клавиша ничего не делает, игра не падает, лог без спама. **Если мод есть только на сервере:** клиенты без мода не могут пинать; сервер не должен кикать таких клиентов при входе (мод не регистрирует обязательные реестры, которые ломают вход).

## Настройки

Один конфиг-файл на стороне сервера (`config/kick.json` или `.toml`), без внешних библиотек конфигов. Значения сервера главные; в одиночной игре — свой конфиг мира/инстанса.

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `damage` | 2.0 | урон в HP (2.0 = одно сердце) |
| `knockbackMultiplier` | 1.5 | множитель горизонтального отлёта |
| `knockbackUp` | 0.4 | вертикальный подброс |
| `cooldownTicks` | 20 | задержка между пинками |
| `reach` | 3.0 | дальность |
| `allowKickPlayers` | true | можно ли пинать игроков (PvP всё равно проверяется) |

Экран настроек в игре — не нужен.

## Версии и загрузчики

Целевая матрица (уточняется при сборке по наличию загрузчиков; одна строка = один jar):

| Minecraft | Fabric (+Quilt) | NeoForge | Forge |
|---|---|---|---|
| 1.20.1 | ✔ | — (NeoForge на 1.20.1 = Forge) | ✔ |
| 1.21.1 | ✔ | ✔ | ✔ |
| 1.21.4 | ✔ | ✔ | ✔ |
| последняя 1.21.x (1.21.10/1.21.11) | ✔ | ✔ | ✔ |
| 26.1.x | ✔ | ✔ | ✔ если Forge есть |
| 26.2 / 26.3 | ✔ | ✔ | ✔ если Forge есть |

Правило: каждая «линия» версий, где менялся API, получает свою сборку; jar объявляет диапазон совместимых патч-версий (например, сборка 1.21.1 работает на 1.21–1.21.1).

Известные точки разрыва API, которые придётся обрабатывать условиями Stonecutter:
- 1.20.5 — новая система сетевых пакетов (payloads) и компоненты данных;
- 1.21.2+ — рендер через «render state», меняется способ анимировать модель игрока;
- 26.1 — Minecraft выходит без обфускации и требует Java 25; меняются маппинги.

## Подходы (выбран №2)

1. **Architectury, ветка на каждую версию** — общий код + обёртки под загрузчики, но каждая версия в своей ветке, исправления переносятся вручную. Отклонено: много ручного переноса.
2. **Stonecutter + Architectury-подобная структура (выбрано пользователем).** Общий код один, различия версий — условными комментариями `//? if >=1.21.2 {`, одна команда собирает все jar. Сложнее настроить сборку, но исправление вносится один раз.
3. **Отдельный проект на каждую комбинацию.** Отклонено: 10–15 копий кода.

## Как устроено (решения)

- **Сборка:** Gradle + Stonecutter для версий; для загрузчиков — Architectury Loom (Fabric/Forge/NeoForge) либо связка Fabric Loom + ModDevGradle; возможна основа на Stonecraft. Выбор конкретного шаблона — за исполнителем, главное: одна команда собирает всю матрицу.
- **Без зависимостей во время игры:** мод не требует Architectury API, Fabric API обязателен только для Fabric-сборки (для клавиш и сети) — это стандарт. Общий код обращается к загрузчику через свой маленький слой-абстракцию (регистрация клавиши, отправка пакетов, регистрация звука/типа урона).
- **Логика пинка** (проверки, урон, отлёт) — в общем коде, сервер-авторитарно.
- **Анимация третьего лица** — mixin в модель игрока (`setupAnim` / его аналог с render state на 1.21.2+), анимация хранится на клиенте по id игрока со временем начала.
- **Анимация первого лица** — отрисовка модели ноги в проходе рендера руки.
- **Mod id:** `kick`, название «Kick! / Пинок» *(моё решение, можно поменять)*.
- **Переводы:** en_us и ru_ru.
- **Звук:** свой .ogg, свободный от прав (сгенерированный или CC0) *(моё решение)*.

## Проверка

- Каждая сборка из матрицы запускается в dev-клиенте: пинок моба (урон, отлёт, звук, анимация), пинок в броне (урон меньше), кулдаун, пинок «в воздух».
- Выделенный сервер + два клиента (хотя бы на одной версии каждой «линии»): видна анимация другого игрока, PvP off блокирует пинок игроков, клиент без мода может зайти.
- Автотесты: юнит-тесты чистой логики (расчёт отлёта, кулдаун, проверка дальности); GameTest там, где загрузчик поддерживает.
